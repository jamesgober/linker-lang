# linker-lang v1.1.0

A symbol's offset was never checked against its section. An object could define a symbol far past the end of its own bytes, and the symbol then resolved into another object's code or outside the image. The entry point and every relocation that named it followed it there, and the link succeeded.

This release checks every symbol against its own object's bytes, and adds three error variants. `LinkError` is `#[non_exhaustive]`, so they are additive.

## Fixed

- **Symbols stay inside their section.** A symbol's offset must lie within its object's bytes in that section, or one past the last byte as an end marker. Anything further is `LinkError::SymbolOutOfRange`.
- **The entry point must name real code.** It has to point at a byte its object contributed. An end marker is a fine symbol but not an entry point, and is refused with `LinkError::EntryOutOfRange`.
- **Overlapping relocations are refused.** Two relocations of one object that patch the same bytes now fail with `LinkError::OverlappingRelocations`. Before, the later one silently overwrote part of the earlier one.

## Upgrading

Objects that linked correctly before link the same way now. A link that relied on a symbol past the end of its section, or on two relocations sharing bytes, now reports an error that names the object and section involved.

```toml
[dependencies]
linker-lang = "1.1"
```
